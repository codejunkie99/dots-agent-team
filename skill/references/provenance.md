# Interface provenance and limits

Checked 2026-09-30 against Model Router 0.5.1 on the development host. Paths below are relative to their installation roots and contain no private credentials. Future versions may change contracts; fail clearly and inspect the current installed sources rather than guessing.

- Router `src/router.mjs`: authenticated `GET /v1/models` publishes `{object:"list",data:[{id,owned_by}]}`; `POST /v1/responses` accepts the OpenAI Responses shape. `/health` is read-only and unauthenticated. There is no assumed Chat Completions endpoint.
- Router `src/caller-auth.mjs` and authentication functions in `src/router.mjs`: existing local caller capability authenticates either a managed capability path or Bearer on the plain loopback `/v1` route. The portable adapter uses Bearer and loopback only; it never logs capability paths or keys.
- Installed `jev-native-agents/scripts/runtime/src/worker.mjs`: `callModel({id,adapter:"codex-router"},{prompt,maxTokens,timeout})` uses authenticated Responses SSE with `x-codex-router-exact-route:1`, blocks OpenRouter, checks explicit completion, and returns requested/resolved model transport information.
- Installed `jev-native-agents/scripts/runtime/src/jev.mjs`: `askJev(state,questions)` uses direct TypeSafe, validates Choice keys/probabilities and privately uses its existing credential owner. Native agent dispatch in that older skill expects `agent_type`; the current collaboration schema differs. This package uses separate CLI workers and does not rely on that incompatible dispatch schema.
- Router `src/jev-model-router.mjs`: its separate built-in `openrouter/jev-auto` route uses OpenRouter Decisions with `~typesafe/jev-latest`. It is not the same adapter as direct TypeSafe. This package does not enable or reconfigure Jev Auto.
- Router `src/chatgpt-session-control.mjs`: safe status projection separates session usability from explicit sharing consent. Native local callers may be blocked while the Codex app’s own session remains usable. Installation cannot grant sharing.
- Jev Computer Use plugin `scripts/jev-client.mjs`: the MCP chooser selects semantic candidates, provides eligibility, and performs no UI execution. Older persistent runner dependencies may be unavailable; use the actual current Codex Computer Use tools.

Official TypeSafe documentation confirms typed choices and a separate host execution layer: [coding agents](https://docs.typesafe.ai/introduction/coding-agents), [use cases](https://docs.typesafe.ai/concepts/use-case-map), [API quick start](https://docs.typesafe.ai/introduction/quickstart), [question primitives](https://docs.typesafe.ai/primitives). The quick start documents `POST https://api.typesafe.ai/v1/systemone`, `jev-latest`, and an observed/versioned response such as `jev-1.13.0`. The environment adapter uses that documented alias and records the returned model.

The local bridge reads published metadata, so a stale catalog or provider credential can still fail. It does not infer task ability from missing benchmarks, prove a best model, or change provider identity from a model label. The worker transport never grants tools. Durable JSON storage belongs to the host. Exact quote matches establish provenance, not semantic correctness. Independent review and task-specific checks remain necessary.

TypeSafe’s [Choice contract](https://docs.typesafe.ai/primitives/choice) defines confidence from the concentration of the per-option probability distribution. It is not a probability that the downstream worker will successfully complete the task. The skill validates the response shape and uses explicit application thresholds; it makes no cross-task calibration claim.
